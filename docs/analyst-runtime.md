# Asterisk Analyst

Authenticated analysts can review a saved run, list its markets, inspect a pick card, ask why a decision was recorded, and inspect measured performance. A question about positions returns the account integration's availability. All reads execute in the caller's authenticated context. The model receives no credentials, principal identifiers, account data or tool results.

Asterisk owns this implementation. Its reference is the [Engineering Agent Kit thin domain profile](https://github.com/craguilar/engineering-agent-kit/blob/ef3e8ad234d6d96b25a058c949219b86ee11fa71/skills/agent-runtime/references/domain-agent-integration.md). The runtime accepts one empty-argument read-tool selection per consultation. Code validates that selection, fetches the evidence and renders the final response. This finite loop intentionally ends after one read. Replies retain source timestamps, model version and data mode where the underlying service supplies them. Follow-up questions use the principal's last tool selection. Cross-session model memory is disabled.

The default local keyword router works offline and identifies itself in each response. To select the optional Claude router, set `ANALYST_PROVIDER=anthropic`, `ANTHROPIC_API_KEY` and `ANTHROPIC_MODEL` on the server. Choosing Anthropic sends the redacted question and previous tool name to that provider. The adapter permits one Messages API request with at most 128 generated tokens. The question is limited to 2,000 characters and the whole consultation has a 10-second deadline. The HTTP service separately enforces per-principal quotas and session ownership. Audits record the tool, status, duration and a hash of its validated arguments. They omit question and result content.

The runtime rejects unregistered tools, model text answers, extra arguments and attempts to override the risk policy. Provider or data failures produce explicit unavailable replies. Source text is data for display. It cannot invoke another tool or enter a prompt. The local router and recorded provider-response tests exercise structure and behavior offline. An opt-in request with deployment credentials is needed to verify a particular hosted model. [Anthropic Messages API](https://platform.claude.com/docs/en/api/messages/create)
